Two enumeration tools disagree on the same host

Status
unresolved
Origin
self-initiated
Started
2026-06-11
Published
2026-06-14

Running two enumeration tools against the same host in my own lab returned different open-port sets. Not a superset and a subset — genuinely different, each finding something the other missed.

I re-ran both with timing options equalised, then serialised them so they were never scanning concurrently. The disagreement persisted, but the specific ports that differed changed between runs, which rules out a stable difference in either tool's default probe set.

What I could not determine is whether this is rate limiting on the host, packet loss in the virtual network I built, or a genuine difference in retry behaviour. All three would produce this pattern, and I do not currently have a way to distinguish them without instrumenting the network layer itself. Leaving it open.
