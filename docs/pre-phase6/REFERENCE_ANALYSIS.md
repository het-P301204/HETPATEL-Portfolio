# Reference Analysis

**Date:** 2026-08-15 · Drawn from four sites rendered in a live browser. Every observation below
is from a render I looked at. Where I am generalising beyond what I saw, it is marked **INFERENCE**.

---

## The single most useful finding

**None of the four references uses a container.** No cards, no panels, no bordered regions, no
metric grids, no sidebars. Across four award-winning sites, zero.

Separation is achieved by **scale, position, colour field, and edge relationship**. That is not a
stylistic preference — it is what the entire reference class does, and it is precisely what the
previous four directions failed to do.

---

## R4 · NOTHIN' — `noth.in` — SOTD + Developer Award

**What I saw.** Caught mid-entrance: a black field with a single white `N` and an apostrophe,
letters assembling. Resolved state: a two-line statement at small size flush top-left
(*"Not a style, a perspective."*), a pill link, and then the wordmark **NOTHIN'** set so large it
**runs off the right edge of the viewport**.

### The three transferable ideas

**1 · Type that does not fit.** The wordmark overflows the viewport. This is the strongest single
device observed — it produces confidence and scale without any decoration, and it makes the browser
window feel like a crop of something larger rather than a container holding something small.

The rejected homepage did the exact opposite: a 553px column centred in 1920px, so the viewport
felt *larger* than the content. **Overflow inverts that relationship.**

**2 · Statement small, wordmark huge.** The sentence carrying meaning is set at ~24px top-left. The
name is set at ~200px. Reading order is by position, not by size — the eye takes the statement
first because it is at the top-left origin, then the wordmark as the field.

**3 · The entrance is the wordmark assembling.** Not a spinner, not a progress bar — the identity
builds itself on an empty field, then the page is there. This is exactly the "identity →
composition → website" sequence the brief asks for, and it costs one animation.

**Does not transfer:** the `BOOK A CALL` pill. That is agency-CTA language and wrong for a personal
portfolio that is not selling services.

## R3 · HAOQI.DESIGN — `haoqi.design` — SOTD + Developer Award

**What I saw.** A saturated deep-blue field. `HAOQI.DESIGN` as a small wordmark top-left. Beneath
it a three-line statement in heavy condensed caps — *"I BRING / CRAFT & TASTE / TO DIGITAL WORK"* —
flush left, tight leading, filling the full width. A dimensional `hello` as a field object. Then
the bio **set in monospace as running prose**. Faint grid lines with `+` marks at the intersections.

### The four transferable ideas

**1 · Monospace for running prose, not for micro-labels.** This is the direct correction to the
error in the previous round. I used mono for dozens of tiny uppercase labels, and a page covered in
tiny mono labels is a developer *tool*. Haoqi sets an actual paragraph in mono and it reads as
*written by an engineer*. **Same typeface, opposite outcome, entirely a function of where it is
applied.**

**2 · Drafting grid with intersection marks.** Faint rules with a small `+` at each crossing. This
is technical geometry that references drawing and measurement, not a security HUD. It carries
"precision" with no lock icons, no scan lines, no matrix. **The best cliché-free technical signal
observed.**

**3 · A saturated colour field, not black-and-grey.** Deep blue, committed, edge to edge. The
previous directions all reached for near-black plus grey plus a warm accent, which is the exact
palette of every security product. A saturated non-security field escapes the category outright.

**4 · Statement large, name small.** Same as R4, independently. Two of two developer-award sites.

## R2 · Emilian — `emilianmisera.com`

**What I saw.** Black field, small logo top-left, and the statement — *"say hello to your creative
developer"* — set very large and **anchored to the bottom-right**, leaving the top ~55% of the
viewport empty. A `HAVE A LOOK` label and a scroll indicator centred beneath.

**Transfers:** **edge-anchoring.** The type is pinned to a viewport corner rather than centred, and
the emptiness above becomes deliberate tension instead of dead space. This is the answer to Het's
objection — he does not want text floating in a giant empty screen, but he also does not want
panels. Anchoring to an edge makes emptiness read as composition.

**Does not transfer, and is worth naming:** the cyan script italic on *creative*, and the animated
mouse-scroll indicator. Both read dated. This is the weakest of the four and it is a useful
demonstration that award-adjacent is not the same as exceptional.

## R1 · Léo Parpeix — `leoparpeix.com`

**What I saw.** A full-bleed 3D illustrated interior. Name at ~24px top-left, `Work` top-right.
No hero text at all.

**Transfers as a principle, not as a technique:** when a **field** carries the impact, the identity
can be small and sit quietly at the edges. Het has no illustration and `MEDIA_POLICY.md` forbids
stock, so his field must be built from **typography, colour or geometry**. The lesson is
structural: *something* must own the viewport, and if it is not the type it must be a field.

**Explicit non-transfer:** the illustration itself. Any attempt to substitute a generic 3D object,
abstract blob or security graphic reintroduces every banned pattern.

## Top 10 art-direction patterns

1. Type that bleeds past the viewport edge.
2. Statement large, name small — reading order set by position, not size.
3. Edge-anchored composition — content pinned to a corner, emptiness as tension.
4. Full-bleed colour field, saturated and committed.
5. Drafting grid with intersection marks as the technical register.
6. Monospace as running prose.
7. Zero containers — separation by scale, position, field and edge.
8. Tight leading and heavy negative tracking at display scale.
9. Asymmetric alignment that changes down the page rather than one fixed measure.
10. The viewport treated as a crop of something larger.

## Top 5 motion patterns

1. Wordmark assembling letter-by-letter as the entrance.
2. Masked line reveals on first paint.
3. Hover states that change *typography* — weight, tracking, position — not background boxes.
4. Scroll that changes alignment or scale, not parallax depth.
5. Page transitions that carry the identity element across.

## Top 5 personal-branding patterns

1. The name is a typographic asset used at multiple scales in multiple places.
2. A statement of stance, not a job title.
3. A recurring identity element that persists across pages.
4. One committed colour that is not a category colour.
5. Restraint in the name's size at the *top* of the page, with authority asserted lower.

---

## What this means for the rejected work

| Error | Reference evidence |
|---|---|
| Cards and bordered panels | 0 of 4 references use a container |
| Mono micro-labels everywhere | R3 uses mono for a paragraph; labels are what make it a dashboard |
| Near-black + grey + warm accent | R3 uses a saturated field; the grey palette *is* the security-product palette |
| Name huge, statement small (direction C) | R3 and R4 both do the reverse |
| Everything centred in one measure | 0 of 4 centre their composition |
| Content sized to fit the viewport | R4's wordmark deliberately does not fit |

**INFERENCE, flagged as such:** four sites is not a sample large enough to call these universal.
Ten high-priority references remain unrendered. The patterns above are consistent across the four
and consistent with the brief, which is enough to design against — not enough to call settled.
