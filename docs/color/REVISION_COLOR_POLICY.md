# Revision Colour Policy

**Date:** 2026-08-14 (Phase 5C)

---

## The policy

**Colour plays no role in the revision system.**

| Element | Colour |
|---|---|
| Revision date | Text muted — same as every other date on the site |
| Revision statement | Text secondary — same as apparatus values |
| Most recent entry | **No distinction** |
| Oldest entry | **No distinction** |
| Publication entry | **No distinction** |
| Marker, dot, bar, or rule | **None** |

The foot register is set exactly like the rest of the apparatus, because that is what it is.

---

## Explicitly rejected

| Rejected | Why it would be proposed | Why it fails |
|---|---|---|
| **Green for current** | Signals what is live | Implies old thinking was wrong in a *bad* way. It was wrong in an ordinary way, which is the point |
| **Red for superseded** | Signals what changed | Turns a correction into an error state. The site's premise is that corrections are good |
| **Orange for "changed"** | Draws attention | Warning vocabulary; the same failure as an uncertainty callout |
| **Glowing / highlighted markers** | Makes revisions noticeable | Decoration; also a social-feed signal |
| Accent on the newest entry | Wayfinding | The newest entry is already last in a chronological list. Position does it for free |
| A coloured timeline rail | Visual structure | A timeline graphic — rejected; also implies more entries than exist |
| Fading older entries | Suggests decreasing relevance | **Older entries are not less relevant.** The record's value is that it is complete |

---

## Why this matters more than it looks

**A colour system would impose a value judgment on the revisions**, and the value judgment would be wrong.

The register's entire meaning is: *here is what I thought, here is when I changed my mind, here is why.* Every entry is equally legitimate. Colouring them differently would say some are corrections of failure and others are the good state — which converts an honest record into a status display.

**The absence of colour is what keeps it a record rather than a changelog.** Release notes are colour-coded because releases have states (breaking, feature, fix). Thinking does not.

---

## What carries meaning instead

| Signal | Mechanism |
|---|---|
| When | The date, in tabular numerals |
| What changed | The statement, in prose |
| Order | Chronological, oldest first |
| That a revision exists at all | The register renders — otherwise nothing |
| Relative recency | Position in the list |

**All textual, all survives greyscale, all readable aloud.**

---

## The one thing colour does do

**Nothing in the register — but the register inherits the page's colour roles**, so it sits at the same visual weight as the head apparatus.

That consistency is deliberate: the head says *what this is*, the foot says *how it changed*. Same register, same treatment, one document.

---

## Test

> **Render the foot register in greyscale. Is anything lost?**

Nothing should be, because nothing was ever encoded in colour.
