# Content Volume Test

**Date:** 2026-08-14 (Phase 5A) · Conceptual test of the visual system at five volumes. **No fake content created.**

---

## 1 investigation

**Surfaces:** Home (identity line → the investigation → contact) · the investigation · About. **No index, no notes section.**

| Question | Answer |
|---|---|
| Intentionally small? | **Yes** — three pages, each complete |
| Excessive whitespace? | No, provided the page ends where the content ends |
| Apparatus meaningful? | **Yes** — status, date, domain, origin are all real |
| Demands absent content? | **No** — sections disappear rather than emptying |

**Risk:** reads as a landing page rather than a body of work. **Mitigated only by the investigation itself being substantial.** The design cannot fix a thin single piece.

---

## 3 investigations — the recommended launch minimum

**Surfaces:** Home (featured + short index preview) · index · investigations · notes (if 2–3 exist) · About.

| Question | Answer |
|---|---|
| Intentionally small? | **Yes** — a tight index of three reads as deliberate |
| Excessive whitespace? | No, if the index uses the tight density specified |
| Apparatus meaningful? | **Yes**, and here it starts doing comparative work — one `open` against two `closed` is information |
| Demands absent content? | No |

**This is the first volume where the system's logic becomes visible**: the reader can see that items differ in status, origin and date, which is the point of having an apparatus at all.

Status filter added. An artifact index may be justified if 15+ artifacts exist.

| Question | Answer |
|---|---|
| Excessive whitespace? | No — a long, scannable index reads as a body of work |

## Where the system is weakest

**At 1 investigation.** Not because of whitespace — the page can be short — but because the apparatus's comparative value requires more than one item. With a single investigation, the reader sees metadata but cannot see what it *distinguishes*.

**This is a genuine and irreducible limitation.** The two-register system is built around the idea that items differ in status, origin and settledness, and one item differs from nothing.

**Recommendation, consistent with `../ux/EMPTY_STATE_AND_GROWTH.md`:** below three investigations, launch as a single-page statement rather than as a portfolio, and adopt the full structure when there are three. The design supports both without change.

---

## Where it is strongest

**At 10–25.** Enough items for the apparatus to reveal patterns — which domains recur, what is still open, what changed after publication — while the index stays scannable without search.

**And it does not weaken past that.** Filtering absorbs 50+; search absorbs more. The compounding asset is the revision history, which only grows.

---

## The volume-independent guarantee

Three properties hold at every volume:

1. **Sections disappear rather than emptying** — nothing advertises a gap.
2. **Layout adapts to content length** — no minimum heights, no padding to fill.
3. **The structure never changes** — an investigation reads the same at n=1 and n=50.

Together these mean **the site never requires content it does not have**, which was the stated objective.
